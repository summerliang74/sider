# 页面切换优化复测

部署提交 f9d0d14，目标 https://siderlearn.com。复测日期 2026-11-03，桌面 Edge 1440×900。用户正常登录后共测试 20 次导航，测试后关闭独立浏览器。

改动：无搜索词的资源列表直接查询；有搜索词时保留事务和 SET LOCAL。Resources 和 My uploads 主导航在悬停、聚焦或触摸时允许完整预取；其他链接保持原策略。未添加权限或会话缓存，未修改数据库结构。

## 结果

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| Resources 稳态列表查询中位数 | 297 ms | 149 ms |
| Resources 稳态数据准备中位数 | 456 ms | 301 ms |
| Resources 普通点击到标题可见中位数 | 705 ms | 586 ms |
| Resources 缓存就绪后的点击中位数 | 未单独测 | 33 ms |
| My uploads 缓存就绪后的点击中位数 | 未单独测 | 33 ms |

服务端优化后使用 5 条稳态日志；首个 Resources 查询 354 ms、数据准备 505 ms，单独排除。普通点击各方向 5 次，缓存就绪阶段各方向 5 次。普通 Resources 点击范围 524–789 ms。My uploads 首次点击 912 ms，后续重复点击 28–41 ms，已经受到客户端缓存影响，不能当作无缓存平均速度。

缓存就绪阶段先悬停，等待匹配响应最多 10 秒，然后再等 200 ms 再点击。本轮该阶段均未观察到新匹配响应、点击时也没有新的匹配资源请求；所以结果表示已有客户端缓存下的切换能力，不能证明每次短暂悬停都能在 33 ms 完成，也不能把提前等待算成消失的耗时。普通点击也可能触发悬停及复用缓存，并非严格禁用预取的对照组。

前后测量时间不同，网络与连接缓存未统一重置；数据库和数据准备的降幅支持减少事务往返的效果，但不是严格的随机 A/B 因果试验。首屏加载和每次导航不保证达到缓存就绪的速度。浏览器首字节也不能代表流式页面的全部服务端等待。

复测未捕获 JavaScript 异常，最后重新加载仍停留于已登录 Resources。搜索事务保留及普通列表跳过事务由现有回归用例验证。89 项单元测试、Lint、严格生产构建、GitHub CI run 41611968626 和 15 项线上冒烟检查通过。
