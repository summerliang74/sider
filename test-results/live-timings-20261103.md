# 线上登录后切换耗时

日期：2026-11-03，Asia/Shanghai。站点：https://siderlearn.com。

用户在独立 Edge 测试窗口正常登录后，自动重复 Resources ↔ My uploads。桌面及手机视口下，每个方向各测试 5 次，总计 20 次。均保持登录状态，未跳转登录页；未上传、删除或修改业务数据。浏览器进程已在测试后关闭。

## 点击开始至目标页面标题可见

| 视口 | 目标页面 | 中位数 | 最小值 | 最大值 |
| --- | --- | --- | --- | --- |
| 桌面 1440×900 | My uploads | 554 ms | 543 ms | 973 ms |
| 桌面 1440×900 | Resources | 711 ms | 684 ms | 720 ms |
| 手机视口 390×900 | My uploads | 589 ms | 561 ms | 674 ms |
| 手机视口 390×900 | Resources | 812 ms | 709 ms | 931 ms |

计时从自动化 click 调用前开始，到 URL 匹配目标路径且 h1 可见为止，包含自动化点击的可操作性等待。手机菜单先打开，再计时点击目标导航项。手机测试仅改变视口，未模拟手机硬件或弱网。没有对独立的新连接、浏览器缓存和路由缓存进行统一清空，因此不能解释为严格的冷启动对比。

公开页面另测 18 次：桌面登录页 load 中位数 278 ms，隐私页 244 ms，条款页 246 ms；手机视口分别为 268、250、246 ms。公开页只有首次桌面登录样本观测到一个 58 ms 长任务。所有视口无横向溢出。测试页面未捕获到 JavaScript 异常。

独立 Node HTTP 探测中，健康接口 5 次 TTFB 为 1163、117、123、154、454 ms；未登录 /api/me 为 756、186、612、178、293 ms，状态均为预期 401。这些来自另一个客户端连接，只用于说明网络/入口等待存在波动，不能与浏览器导航样本直接相减。

## 判断与限制

实际登录后切换通常需要约 0.55–0.81 秒，Resources 比 My uploads 慢。当前数据证实存在可感知的页面切换等待，但没有定位到具体数据库查询或服务端阶段。本次业务导航的请求级时间采集未获得匹配样本（requests 数组为空），因此不能宣称耗时全部来自服务端或数据库，也不能将公开页面与业务页面的差值当作数据库耗时。

下一步定位需要在登录后的 RSC 请求上补充准确的请求匹配和 TTFB 采集，再按会话验证、资源列表、标签查询记录服务端分段耗时。当前可优先评估主导航按需预取、普通列表减少事务往返、标签短时缓存；优化前后应复用同样的登录导航测试流程。
