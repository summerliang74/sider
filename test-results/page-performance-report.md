# 页面性能测试记录

测试日期：2026-11-03（Asia/Shanghai）。目标：https://siderlearn.com。

使用本机 Edge 无头浏览器，桌面 1440×900、手机视口 390×900，每条路径连续访问三次，共 36 次。另测四次公开链接点击。手机测试只改变视口，没有模拟手机 CPU 或弱网。原始数据见 page-performance.json，脚本见 ../.tmp/page-performance.cjs。

## 切换慢的代码线索

1. src/components/app-shell.tsx 主导航和 src/components/resource-list.tsx 详情链接显式设置 prefetch={false}，点击后才发起相应页面请求。
2. app 下没有 loading.tsx；数据库和网络等待期间缺少路由级加载反馈。
3. app/resources/page.tsx 先验证会话，然后等待 listResourceTags，之后再等待 listActiveResources。标签和列表读取存在可并行空间。
4. src/lib/auth/session.ts 每次带会话的请求都会查询数据库；网络与数据库延迟会进入页面切换关键路径。未对登录后的查询耗时进行实测，因此这些是待验证的优化线索，不是已证实的唯一根因。
5. 手机登录页 auth-editorial 与 auth-panel 超出视口，需单独修复布局。

## 覆盖范围与限制

访问 /resources、/me/resources、/resources/new 均正常重定向至登录页；这些记录只证明登录保护和跳转可用，不能作为登录后业务页面的性能结果。本次浏览器没有用户登录态，未访问私人资源、未上传或删除文件、未修改线上配置。

本地 npm test：25 个测试文件、89 个用例全部通过。单元测试不等同于页面性能测试。

建议先补路由加载反馈，验证会话传递后再考虑导航预取，并将资源列表与标签查询并行；随后使用正常登录的浏览器测 Resources → My uploads → 详情的 RSC 请求、TTFB 和数据库耗时，以确认瓶颈。此次仅完成测试与记录，没有修改产品代码或部署。
