## 对齐规则

| 场景 | 当前Java行为 |
|---|---|
| 页内导航 | 普通同源页面链接在当前文档切换，显示原版顶部加载条；Ctrl/Meta/Shift、target、下载及锚点保留浏览器行为 |
| 浏览器返回/前进 | 重新核对本站身份，恢复该历史项的搜索草稿、展开筛选、已加载结果和滚动位置；历史记录只保存标识，数据快照只在当前标签页内存中保留 |
| 搜索 | 只有提交才使用输入草稿；更换标签/类型仍使用已提交查询；操作时replaceState，初次打开保留原URL；清除与筛选标签行为沿用原版 |
| 搜索验证 | 显示行内验证；追加结果遇验证时保留已加载卡片并隐藏后续分页，完成验证后恢复该次搜索 |
| 登录 | `Connecting…`、禁用态、`Continue`、验证后显式继续及错误反馈沿用原组件；Cookie/header-compat仍按部署明确配置 |
| 详情操作 | 编辑、举报、管理员移除互斥；举报菜单在Report/Close间切换；管理员移除使用原因表单；保存关闭编辑、保留成功提示并刷新当前页面数据 |
| 下载/举报验证 | 展示原准备/验证提示，验证完成后等待用户再次点击对应操作，不在验证码回调中自动执行下载或举报 |
| 上传队列 | 每项验证进入该项待处理状态并释放并发槽；验证后重试该文件；无效类型只影响其对应行，有效文件继续；相同意图重试与未知结果保护继续生效 |
| 新批次 | 原位清空队列、文件、字段、标签、验证和轮询，保持当前文档，不整页重新加载 |
| 我的上传 | 取最近100条所有状态，先计算摘要再筛选；有扫描中记录时按原10秒周期刷新整个窗口，全部扫描结束后停止 |
| 管理列表 | 原版open举报最早100条与审计最新200条窗口；提示、原因prompt取消和动作后的刷新行为沿用原版 |
| 离页 | 页面请求、验证码、上传与轮询绑定所属页面；离开后迟到的搜索、SDK或其他异步工作不再覆盖新页或触发旧导航 |

后台的默认签名游标分页仍保留；页面使用新增 `view=workspace` 明确请求原版固定窗口。接口参数、上限及拒绝组合见 [API设计](API-DESIGN.md) 和 [OpenAPI](openapi.yaml)。
