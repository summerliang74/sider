# Sider Java 版本产品需求与迁移 PRD

> 版本：Implementation v1.1 · 2026-11-11（Asia/Shanghai）
> 决策：用户已选择 Java 后端、原生 HTML + CSS + JavaScript 前端、沿用 PostgreSQL。
> 当前阶段：Java业务代码、原生前端、容器/平台计划与本地测试已实现；尚未构建或发布Launchpad Java镜像，尚未切换生产流量。已执行隔离本地数据库测试，未操作生产数据库。证据与限制见 [实施状态](JAVA-IMPLEMENTATION-STATUS.md)。
> 工作分支：`codex/java-api-design`。

## 1. 目标与文档关系

将现有 Sider 学生学习资源共享平台迁移为 Java 后端与原生网页前端，在可独立部署的新版本中保留登录、资源检索、文件直传与后台扫描、下载、本人资源管理、举报和管理员治理。

本 PRD 定义新版本的产品范围、技术责任与验收门槛；[API 设计](API-DESIGN.md)与 [OpenAPI 合同](openapi.yaml)定义 HTTP 请求和响应；[数据库访问设计](DATABASE-ACCESS.md)定义表、查询、事务和迁移边界；[部署环境](DEPLOYMENT-ENVIRONMENT.md)定义主机、运行时、端口、配置作用域与发布门槛。[文档审计](DOCUMENTATION-AUDIT.md)记录旧资料适用范围。各合同必须同步更新。发生冲突时先修正文档，不由实现自行选择一种解释。

既有 [MVP PRD](../SHSID-Online-MVP-PRD.md)、[完整路线图](../SHSID-Online-PRD.md)及历史验收记录继续保存，描述原版本及原有产品背景。新版本的技术栈、API 与迁移验收以本组设计为准；原版本的测试和上线记录不能直接视为 Java 版本的通过证据。

## 2. 范围与成功条件

### 2.1 设计与实施交付

1. 可供审阅和拆分实施任务的 PRD，明确 P0、P1 与待验证事项。
2. 前端可据此开发的 API 设计与可机器校验的 OpenAPI 3.1 文档。

上述设计已用于实现 `backend/` 的Java服务与原生页面，并补充Java CI、Dockerfile、Launchpad源码打包与运行时配置引用。已执行本地构建和隔离真实PostgreSQL测试，生产DDL/DML、平台构建/发布及生产登录配置变更均未执行。第11节保留各里程碑退出条件；代码存在不代表其托管、外部服务与生产验收已通过。

### 2.2 Java 版本 P0

- 只有持有效 Launchpad 身份、本站状态为 active 的用户可使用业务功能。
- 在统一资源库中搜索标题、描述、文件名与标签；支持文件类型及单个标签组合筛选。
- 一次选择 1–5 个独立文件，最多 2 个文件并行直传到私有存储，后台扫描后发布。
- 查看资源、下载已发布文件、编辑和删除本人资源，查询上传处理状态。
- 学生举报；管理员查看与处理举报、隐藏/恢复/下架资源、封禁用户及查看审计。
- 分层共享限流、风险挑战、严格同源防护、最小权限、备份恢复与可观测性。

### 2.3 不纳入 P0

Q&A、评论、聊天、点赞/收藏、推荐算法、在线文件预览、多文件资源包、压缩包、普通账号密码登录与邀请注册。SHA-256 必须作为扫描证据保存；基于哈希的重复文件提示为 P1。搜索高亮和现有全文/模糊搜索属于需迁移的既有功能，不借迁移降级为仅标题匹配。

## 3. 技术选型与责任划分

| 层 | 目标方案 | 责任 |
|---|---|---|
| 页面结构 | HTML | 登录、列表、详情、上传、管理等语义化页面与表单 |
| 样式 | CSS | 保留现有安静、文档工具式视觉；响应式、键盘焦点、错误与加载状态 |
| 浏览器交互 | 原生 JavaScript ES Modules | 请求 API、状态更新、上传队列；不引入 Vue、React、Next.js 或 TypeScript |
| 后端 | Java + Spring Boot / Spring MVC | 身份准入、会话、业务校验、授权、REST API、任务管理 |
| 数据访问 | Spring JDBC、参数化 SQL、HikariCP、PostgreSQL JDBC 驱动 | 显式查询、事务、连接预算、结果映射 |
| 持久化 | 现有 PostgreSQL | 复用用户、会话、资源、任务、举报与审计数据 |
| 文件 | 现有私有 S3 兼容存储 | 浏览器短期签名直传/下载，服务端冻结快照与管理对象 |
| 安全依赖 | 现有共享限流、挑战校验、独立恶意软件扫描 | 保留外部服务合同与拒绝放行策略 |

前端是逻辑独立的静态资源，优先与 Java API 共用一个 HTTPS origin；可由 Spring Boot 或受控反向代理提供。浏览器不得直接访问数据库或取得长期存储凭据。后端使用 DTO，不能把完整数据库行直接序列化到响应。

当前工程使用Java21、Spring Boot4.1.2与Maven3.9，已生成本地可执行JAR；仓库尚未提供Maven Wrapper。`backend/Dockerfile` 定义Java21多阶段构建与非root运行，实际镜像可拉取性、构建/启动及平台资源仍待验证；本地构建成功不代表生产镜像已验收。

### 3.1 托管和登录边界

用户确认应用部署环境为 **Launchpad**：Java后端与原生页面运行在现有Launchpad项目的受管理Docker容器中，域名、HTTPS入口和同源 `/dashboard-api/` bridge由平台承接。平台手册支持Dockerfile部署，但目标Java镜像的构建、配额、启动/监听、SDK callback及Cookie透传仍须验证。设计监听0.0.0.0:8080并与平台port计划一致，不使用容器回环绑定阻断gateway访问。

UCloud仅承载独立扫描服务，按仓库AGENTS.md保留 `/root/.openclaw`。其2核/4GB等规格只用于scanner/ClamAV及共存应用预算，不是Launchpad应用额度。Java不部署到UCloud，不要求在那里增加Java systemd/Nginx配置；平台出站到扫描HTTPS端点、各自资源预算和重启恢复见部署环境。本次不发布或改变两端运行配置。

### 3.2 会话传输决策

- 目标首选：同源 `HttpOnly + Secure + SameSite=Lax` Cookie，会话最长 3,600 秒；必须验证入口、反向代理和应用返回的 `Set-Cookie` 在真实浏览器端完整生效。
- 兼容配置：仅在托管链路仍无法可靠透传 Cookie 时显式启用现有 IndexedDB + 同源 Service Worker + `x-sider-session` 方式，沿用原版风险边界和回归检查，不允许运行时悄悄回退。
- 两种配置使用同一套本站会话和数据库 token 哈希；不得混入第二套客户端身份判断。默认配置不得把本站 token 返回给脚本。
- Launchpad SDK 为 PKCE 临时状态使用的 sessionStorage 与本站长期会话不同；不得把本站 token 或 Launchpad access token 另存 localStorage/sessionStorage。

## 4. 角色与权限

| 角色 | 可用能力 |
|---|---|
| 访客 | 登录、隐私、条款、错误页及最小公开运行配置；不取得资源或用户数据 |
| active 学生 | 搜索、查看 active 资源、下载、上传、查看本人资源状态及删除记录、编辑/删除本人资源、举报他人 active 资源 |
| 管理员 | 学生能力，以及查看未删除资源的治理元数据、编辑/删除资源、处理举报、隐藏/恢复/下架、封禁用户和查看审计 |
| suspended 用户 | 不得创建或继续使用本站会话，不得获得新上传/下载签名 |
| 内部任务调用方 | 只凭独立服务凭据访问指定任务/就绪端点，不具有学生或管理员身份 |

管理员身份由服务端配置的 Launchpad `sub` 白名单决定。客户端字段、邮箱后缀、用户可编辑资料均不能赋予管理员权限。移除管理员资格后，下一次请求纠正角色并撤销旧管理员会话。

普通浏览者只可查看 active 详情。作者与管理员可查看非 deleted 资源的处理状态及必要元数据；这不赋予其下载扫描未通过文件的权限。所有角色对非 active 文件均不能取得下载签名。对无权查看、不存在和已删除的资源统一返回不可用结果，避免枚举信息泄露。

## 5. 用户流程与功能需求

### 5.1 登录与退出

| ID | 优先级 | 可验收要求 |
|---|---|---|
| J-AUTH-01 | P0 | 页面通过同源 Launchpad 官方 SDK 发起 Code + PKCE；SDK 管理 verifier、state、nonce 和保留 callback；Java 服务不再维护第二套 code 交换状态机 |
| J-AUTH-02 | P0 | Java 仅接受 SDK access token，用服务端 userinfo 响应确认 sub 并检查本站封禁；不接受客户端上报的 role/sub/org 作为身份事实 |
| J-AUTH-03 | P0 | sub 唯一；email 为可更新资料；org/verified 保存为身份快照；allows 仅校验，不保存且不作为当前准入门槛 |
| J-AUTH-04 | P0 | 数据库只保存高熵随机 token 的加 pepper HMAC 哈希；绝对期限不超过一小时，不使用滑动续期绕过上限 |
| J-AUTH-05 | P0 | 退出成功时服务端撤销本站会话并清除 Cookie 或兼容存储；多标签页同步退出。撤销请求失败不得宣称旧 token 已失效，提供重试；本地清除与服务端撤销结果分别处理 |
| J-AUTH-06 | P0 | 封禁与会话创建、扫描发布之间存在明确事务序列；封禁提交后不再创建有效会话或发布该作者的待扫描文件 |
| J-AUTH-07 | P0 | 共享 Redis 原子保留域分离 HMAC 后的 Launchpad access token 指纹，保留期 3,900 秒；单次交换总处理时限 ≤60 秒，覆盖随后创建的最长 3,600 秒会话。并发/重复交换返回 409，不创建多个同时有效的本站会话。不存原始 token；预留后失败或响应丢失要求重新授权，不在数据库提交结果不明时释放指纹 |

Launchpad 目前仅面向 SHSID 的前提继续沿用；若平台开放校外用户，必须在开放前重新设计服务端准入规则。正常取消授权和平台故障不当作密码攻击。

现有 callback 通过白名单参数（code、state、error、error_description，每项最多 4,096 字符）重定向回登录页，由 SDK 继续处理；迁移时保持该 SDK 合同，避免把浏览器 callback 误实现为 Java 服务端交换 code。重复交换保护只覆盖最长本站会话窗口，不宣称 access token 在其整个生命周期内只能使用一次。

### 5.2 发现与搜索

| ID | 优先级 | 可验收要求 |
|---|---|---|
| J-SEARCH-01 | P0 | 统一 `/resources` 页面，不设独立 PA 分区；搜索与文件类型、标签筛选可组合 |
| J-SEARCH-02 | P0 | q 去首尾空格，最多 120 字符；空查询按发布时间/id 倒序；非空按相关性、发布时间/id 倒序；新合同不提供无实现依据的 sort 参数 |
| J-SEARCH-03 | P0 | 只返回 active；每页 20 项，使用稳定 keyset 游标；查询/筛选改变必须从第一页开始，游标绑定其查询指纹 |
| J-SEARCH-04 | P0 | 保留 PostgreSQL 全文、trigram 模糊匹配与安全的高亮片段；高亮文本通过 textContent 创建 DOM，不执行服务端返回的 HTML |
| J-SEARCH-05 | P0 | 标签去重且不区分大小写；PA 及 NFKC/去标点后的 peer advisor(s) 别名归一为 PA。所有学生可筛选 PA，仅管理员可赋予 |

学生提交的完整 tags 列表只要包含 PA 别名即拒绝，包括原样提交管理员已赋予的 PA；学生可移除 PA 后保存，或由管理员保留 PA 并编辑。前端必须说明这个限制，不能让服务器静默放行。

兼容旧 `collection=peer-advisors` 为 PA 标签过滤；显式 tag 优先。前端新链接使用统一 tag 参数。分页保证固定结果集合中的稳定顺序，不声称在并发编辑、发布和删除下具有跨请求数据库快照一致性。

### 5.3 文件发布与处理

| ID | 优先级 | 可验收要求 |
|---|---|---|
| J-UPLOAD-01 | P0 | 单批 1–5 个独立资源，共享表单元数据，最多两条文件传输并发；逐文件进度、错误、重试、取消，一项失败不阻断其他项 |
| J-UPLOAD-02 | P0 | title 1–120 字符，description ≤2,000，tags ≤10 且每项 1–30；文件名清理路径/控制符并限制 255；大小默认最大 50 MiB（52,428,800 字节），配置硬上限 500 MiB |
| J-UPLOAD-03 | P0 | 白名单 PDF、DOCX、PPTX、XLSX、TXT、PNG、JPG/JPEG；声明扩展名/MIME 必须匹配，扫描再验证真实类型；拒绝脚本、可执行文件、宏文件和压缩包 |
| J-UPLOAD-04 | P0 | 创建 intent 后返回 300 秒预签名 PUT，绑定对象、长度、类型和资源标识；文件正文直达私有存储，不经过 Java 应用 |
| J-UPLOAD-05 | P0 | complete 仅作者可调用；校验意图年龄不超过一小时、HEAD 元数据、ETag 条件复制和专用快照，再在一个事务中 CAS pending→scanning 并插入唯一任务 |
| J-UPLOAD-06 | P0 | complete 重试不重复创建任务；已 scanning 返回原状态，已 active 返回已完成状态，已删除不可复活；新 intent 的 POST 非幂等，丢失响应后的孤儿记录由清理处理 |
| J-UPLOAD-07 | P0 | worker 正常全局扫描并发为 1；五分钟租约、唯一 lease token、崩溃回收和提交 fencing；最多尝试三次，临时失败间隔 30/60 秒，持有租约结束后旧 worker 不得提交 |
| J-UPLOAD-08 | P0 | 只扫描冻结快照，clean + 合法 detected MIME + 有效 SHA-256 才可发布该份内容；感染/类型不符/重试耗尽隔离；删除、封禁与租约丢失均阻止发布 |
| J-UPLOAD-09 | P0 | 本人资源页通过分页 API 取得列表；上传页或本人资源页需要轮询时调用 POST /api/resources/upload-status，每请求最多五个本人资源 ID，超出分组查询；轮询有退避，隐藏页面暂停，终态停止，处理 401/429/503 |
| J-UPLOAD-10 | P0 | 浏览器取消传输并请求删除已知 intent；abort 不代表存储端删除成功，未完成对象由延迟清理兜底；已发布资源不支持覆盖替换文件 |

状态机以 [API 设计](API-DESIGN.md)和 [数据库访问设计](DATABASE-ACCESS.md)为准：pending→scanning→active 或 quarantined；pending→failed；active↔hidden；作者/管理员删除任意非 deleted 状态→deleted。quarantined 不允许管理员直接恢复为 active；需重新上传扫描。

旧流式上传接口由 `LEGACY_UPLOAD_ENABLED` 明确控制，默认false并返回410 `legacy_upload_disabled`；新前端不调用它。仅在评估旧客户端后显式开启时提供中转，并仍走相同快照与扫描发布路径。切换前记录兼容窗口和移除门槛。

### 5.4 详情、作者管理与下载

| ID | 优先级 | 可验收要求 |
|---|---|---|
| J-RESOURCE-01 | P0 | 显示标题、描述、标签、文件名、类型、大小、作者显示名、时间；作者/管理员补充状态，不返回 object key、扫描内部路径和凭据 |
| J-RESOURCE-02 | P0 | 作者与管理员可修改本人/受治理资源的元数据；每次重新校验角色、资源权限、状态与 PA 规则；元数据修改采用最后成功提交覆盖，前端同一表单禁止重复提交 |
| J-RESOURCE-03 | P0 | 作者通过 DELETE 删除本人资源；管理员删除他人资源走带必填原因的 moderate/remove。软删除立即阻止新签名；状态更新与审计同事务；数据库提交成功不等于存储对象已物理删除 |
| J-RESOURCE-04 | P0 | 下载签名前重新验证 active 用户、资源 active 和风险检查；预签名 GET 固定有效期 120 秒，响应不被缓存 |
| J-RESOURCE-05 | P0 | 资源被隐藏/删除后停止为该资源签发新链接；请求者被封禁后不得再取得任何新链接。已经签发的链接可能持续到期，不承诺立刻撤销 S3 已签发 URL |
| J-RESOURCE-06 | P0 | 本人资源分页 API 提供全部处理状态及 deleted 的最小历史元数据；deleted 项无详情/下载/编辑入口，其余本人未发布项可管理；不提供文件预览 |

作者被封禁会阻止其继续使用本站及其待扫描资源发布；不会自动隐藏其先前已经 active 的资源。其他 active 用户仍可下载这些资源，若内容也需下架，管理员必须执行资源治理并记录原因。

### 5.5 举报和管理

| ID | 优先级 | 可验收要求 |
|---|---|---|
| J-MOD-01 | P0 | 学生对他人 active 资源提交版权/隐私、恶意文件、不当内容、垃圾内容或其他举报；同一用户/资源最多一个 open 举报，由数据库唯一索引兜底 |
| J-MOD-02 | P0 | 管理员分页查看举报队列和审计；以明确动作及原因关闭举报；处理与审计原子提交，冲突返回明确结果 |
| J-MOD-03 | P0 | 隐藏仅对 active，恢复仅对 hidden，下架软删除；操作时重新验证状态，不能借恢复绕过扫描 |
| J-MOD-04 | P0 | 禁止管理员封禁自己；封禁目标用户与撤销其全部未撤销会话、管理审计同事务；并发登录和扫描发布必须遵守相同用户行锁顺序 |
| J-MOD-05 | P0 | 审计包括操作者、时间、对象、动作、必要脱敏原因；元数据修改仅记录字段名/角色，不复制资源标题、描述或标签正文，不保存 token 或签名 URL |

## 6. 页面与交互

| 页面 | 主要行为 |
|---|---|
| `/login`、`/__lp_auth/callback`、`/auth/error` | SDK 登录、回调与明确错误，不自行重复 code 交换 |
| `/resources` | 搜索、类型/标签筛选、高亮、下一页、空结果和挑战处理 |
| `/resources/new` | 共享元数据表单、逐文件上传与扫描状态、取消/重试 |
| `/resources/{id}` | 详情、下载、举报及按角色显示的编辑/删除 |
| `/me/resources` | 本人资源、处理状态与管理动作，deleted 仅显示历史元数据 |
| `/admin/reports`、`/admin/audit` | 举报队列、治理/封禁动作及审计 |
| `/privacy`、`/terms`、错误页 | 公开规则、隐私说明、404/不可用提示 |

静态 HTML 外壳不能被当作授权边界：业务数据全部来自受保护 API。按钮隐藏仅改善交互，服务端必须独立授权。刷新、直达链接和浏览器前进后退需可用；主流程支持移动端、键盘和基础 WCAG 2.1 AA。所有用户文本按纯文本输出，不接受任意 HTML。

## 7. API 与数据访问边界

- 保留 `/api` 主要路径，新增原先依赖服务端渲染的本人资源、标签和审计 API。详细参数、响应、状态码与错误码由 OpenAPI 单独定义，页面 URL 不混入业务 API 列表。
- JSON 使用 camelCase、UTC ISO 8601 时间、UUID 标识；sizeBytes 为字节整数。API 错误只输出安全代码、必要字段错误及请求标识。
- 写操作在业务处理前验证 Origin/Fetch Metadata；Cookie 的 SameSite 不替代同源检查。内部任务服务凭据单独校验，不要求浏览器 Origin。
- 执行顺序：受信 IP 粗限流→会话/用户查询→用户/操作限流→风险挑战→业务查询和外部存储操作；拒绝时不提前启动高成本下游工作。
- Spring Service 划定事务；Repository 只执行参数化 SQL。数据库 enum、text[]、jsonb、timestamptz、bigint 和生成列必须有明确 JDBC 映射，生成搜索列不得由 Java 手工写入。
- 继续使用现有数据库表、主键、对象 key 与 token 哈希约定；设计阶段不修改迁移文件或迁移 journal。独立评估旧会话是否复用或在切换时撤销，不默认为 Java 无需验证即可识别。新签名游标增加服务端配置 CURSOR_SIGNING_KEY，独立随机密钥至少 32 字节；旧无签名游标不兼容，新前端须清空并从第一页查询。
- 慢速网络扫描与存储复制不置于长数据库事务；对象存储与 PostgreSQL 不存在分布式原子提交，必须用快照、CAS、租约和可恢复清理明确处理中间失败。

## 8. 安全、运行与性能

| ID | 优先级 | 要求 |
|---|---|---|
| J-SEC-01 | P0 | 生产 HTTPS，CDN/WAF/origin 隔离，应用只信任受控代理覆写的客户端 IP；无公网直达绕过 |
| J-SEC-02 | P0 | 多实例共享原子限流；超额 429 + Retry-After，外部依赖失败不以本机内存计数或假服务自动替代 |
| J-SEC-03 | P0 | 风险挑战验证有效期、hostname、action、重放；高风险请求校验失败不得放行；低风险读降级策略须显式定义并测试 |
| J-SEC-04 | P0 | 受保护响应及含签名/token 的响应 no-store；日志、审计、URL、监控不保存原始凭据、完整签名 URL 或文件内容 |
| J-SEC-05 | P0 | 数据库运行账户最小权限，DDL 使用独立迁移账户；生产连接验证 TLS，密钥以运行环境注入，启动校验缺失和占位配置 |
| J-SEC-06 | P0 | 兼容 Service Worker 不为跨域或 /dashboard-api/ 注入本站会话头；携会话头的受保护请求不得跟随跨域重定向（拒绝重定向或手动限制为同源）。受保护响应不得进入 HTTP/Service Worker 或持久化页面缓存；只允许当前标签页内短期复用白名单页面元数据（30 秒、最多 24 项，写操作/退出/未授权时清除），不含凭据、下载链接或文件正文。会话过期后清除兼容存储并跳转登录 |
| J-OPS-01 | P0 | 默认每实例数据库连接上限 5，乘实例/worker 数后不超配额，并预留迁移与维护连接；读写超时有界 |
| J-OPS-02 | P0 | 存活检查不泄露基础设施；受保护就绪检查覆盖必需服务；结构化记录延迟、错误码、扫描队列、租约恢复、限流和挑战指标 |
| J-OPS-03 | P0 | 删除对象默认保留 7 天；过期 pending 一小时后对账；任务副本在 URL/租约安全窗口后清理；活跃任务输入不得删除 |
| J-OPS-04 | P0 | PostgreSQL 备份、恢复、迁移前验证、回滚/前向修复与旧版本回切均有演练证据 |
| J-PERF-01 | P0 | 常规页面服务端响应 P95 ≤1 秒，搜索 API P95 ≤800ms（不含文件传输）；明确测试数据规模、并发与冷热状态后验收 |

保留原版搜索 60 次/分钟/用户、120 次/分钟/IP，上传 intent 10 次/小时/用户、30 次/小时/IP，complete 20/60 次/小时，下载 120/300 次/小时，举报 10/30 次/天作为内测起点。本人状态轮询、标签、管理及会话交换配额在 API 设计中补齐；校园共享出口登录容量必须专门验证。

## 9. 数据兼容与切换条件

1. 在隔离测试数据上核对现有 schema、七条迁移、生成搜索列、索引与历史 journal；不把新建空库当作迁移兼容证据。
2. 复用现有表名、UUID、资源元数据、状态与对象位置。JDBC 访问不会自动取代 schema 管理；迁移工具交接另行明确。
3. 首版不要求新增版本列、幂等键表或重建业务表；若后续发现必须增补约束，采用独立、向后兼容迁移并评估旧版本回切。
4. 不同时让新旧 worker 无协调地领取同一队列；并行验证需共享相同 advisory lock key、租约语义与提交 fencing，或使用完全隔离的数据。
5. 登录回调、旧会话传输和浏览器 Service Worker 退出/更新策略需联合验证；移除旧 Service Worker 后不可残留会话头注入或缓存数据。
6. 生产切换前记录旧客户端兼容窗口、数据和对象备份、回切步骤及监控门槛。只替换应用代码不能被视作已完成部署迁移。

## 10. 验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| SDK 回调 state/nonce 错误、过期 code、userinfo 拒绝 | 不创建本站有效会话，不重复交换 code，错误脱敏 |

| 用户被封禁或管理员被移除 | 旧会话失效；并发创建会话/发布不能绕过已提交的封禁 |

| 同批五文件，一项失败或取消 | 最多两个并发，独立重试/清理；其余文件可继续 |
| 50 MiB 边界、超大、伪造类型/长度/资源标识 | 不合规上传无法发布；以真实浏览器和存储校验 CORS 与签名绑定 |
| complete 并发与响应丢失 | 每资源至多一个任务；不重复入队，不删除已提交任务快照 |

| 扫描时删除/封禁、恶意文件或类型不符 | 不发布，不可下载；审计和终态一致 |
| 元数据/治理/封禁操作中审计写入失败 | 整个数据库事务回滚，不留下无审计变更 |
| 软删除与清理并发 | 不签发新链接，不删除活跃任务输入；中断可重试 |
| 未登录/学生访问管理 API 和私有数据 | 401/403 或统一资源不可用，不泄露状态/存储路径 |
| 限流/挑战/存储/扫描故障 | 按合同返回 429/503，拒绝后不启动业务及存储工作 |
| 历史数据与旧版回切 | 新版能正确读取存量；未验证前不改写迁移历史或删除旧表 |
